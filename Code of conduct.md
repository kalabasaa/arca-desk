 <h1 align="center">Code of Conduct</h1>

## Project Responsibility

Every contributor is responsible for understanding the code they introduce into the project.

# Rules

1. **Follow the Existing Architecture.** Do not create a separate project structure or replace existing implementations.
2. **Understand Before Modifying.** Inspect the existing forms, `UserControl` pages, namespaces, and navigation before making changes.
3. **Reuse Existing Components.** Do not duplicate functionality that already exists in the project.
4. **Avoid Unnecessary Refactoring.** Do not rewrite working code simply because an AI tool suggests a different approach.
5. **Test Before Pushing.** Ensure the project builds successfully and all changes work as expected before pushing.
6. **Communicate Before Major Changes.** Ask for approval before modifying shared components or existing functionality.
7. **Make Small, Meaningful Commits.** Keep commits focused on specific changes and use clear, descriptive commit messages.
8. **Explain Your Code in Pull Requests.** Describe your changes, explain how your implementation works, and mention the tests performed. Contributors must understand and be able to explain the code they submit.

## Unacceptable Behavior

- Disregarding agreed project guidelines and development standards.
- Making significant changes without proper communication or approval.
- Overwriting, deleting, or restructuring existing implementations without authorization.
- Submitting untested or unverified code.
- Ignoring feedback or refusing to address issues with submitted contributions.

## Enforcement

Project maintainers are responsible for addressing violations of this Code of Conduct.

Depending on the severity and frequency of violations, maintainers may:

1. Issue a reminder or warning.
2. Request corrections or revisions to submitted contributions.
3. Restrict access to certain parts of the project.
4. Reject contributions that do not meet project standards.
5. Remove a contributor's access to the repository.

## Scope

This Code of Conduct applies to all project-related activities, including repository contributions, code reviews, discussions, and other forms of collaboration.

## Final Statement

Arca Desk is a collaborative project. Contributions are welcome, but every contribution must respect the existing work, project structure, and agreed development standards.

**Collaboration requires accountability, communication, and respect for the work of others.**
